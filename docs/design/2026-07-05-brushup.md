# jilog brush-up: health signals, cost-weighted digests, release hygiene

Status: approved design, 2026-07-05. Work tracked in kata (project `jilog`, parent
issue `d3ck`). Catalog registration (microsoft/amplifier MODULES.md) is on hold
until this lands; the earlier registration PR (#308) was withdrawn deliberately.

## Context

Three things changed around jilog in mid-2026:

1. Amplifier's context-intelligence bundle ships a library of mechanical
   session-health signals (compaction storms, stuck loops, resume storms,
   iteration runaway). jilog now reads that bundle's JSONL stream (reader added
   2026-07-05, commit 28f12a9) but detects none of those patterns itself. The
   `Signal::Pattern` variant has been reserved since the enum was written.
2. Amplifier providers now stamp `cost_usd` per LLM call into the session files
   jilog already reads. Sub-agent session ids carry the agent name, so per-role
   cost attribution is available with no new data source. (Fable models cost
   `null` until upstream PR microsoft/amplifier-module-provider-anthropic#65
   or equivalent lands and rates are configured.)
3. beads is deprecated in the author's stack (kata replaced it); the beads
   tracker is dead weight for a public release.

## Goals

- W1. Release hygiene: first tagged release, CI badge, sample digest and
  5-minute quickstart in the README.
- W2. Health-pattern detectors: four mechanical signals as pure-Rust detectors
  emitting `Signal::Pattern`.
- W3. Cost-weighted digests: per-session/per-role spend summarized in the
  nightly digest and the week-over-week check.
- W4. Remove the beads tracker.

## Non-goals

- NanoClaw reader (separate follow-up; README continues to mark it planned).
- LLM-assisted signal classification (rejected for now; core stays Rust-pure,
  no API key required — this is identity, not a gap).
- mempalace/bundle-memory reader (blocked on upstream write-path fixes;
  kata `4s2z`).
- Any call-level tracing ambitions. The README's "why not Langfuse" position
  is unchanged: cost appears here as *weighting on learning signals*, not as
  per-request telemetry.

## W2 design: health-pattern detectors

New event-level input path, additive to the reader trait:

```rust
/// Kernel-ish session events for detectors that need more than messages.
pub struct SessionEvent {
    pub kind: SessionEventKind,   // Compaction | Resume | ToolCall | LlmResponse | UserMessage
    pub timestamp: DateTime<Utc>,
    pub tool_name: Option<String>,
    pub detail: Option<String>,
}

pub trait Reader {
    // existing: name / discover / load
    /// Optional richer stream. Default: Ok(None) — reader has messages only.
    fn load_events(&self, handle: &TranscriptHandle)
        -> Result<Option<Vec<SessionEvent>>, JilogReviewError> { Ok(None) }
}
```

`amplifier` and `context-intelligence` readers implement `load_events` (their
JSONL already carries `context:compaction`, `session:resume`, `tool:pre/post`,
`llm:response`). The other readers keep the default; health detectors simply
produce nothing for them. This degradation is documented in the README readers
table (a "health signals" column).

Four detectors (thresholds from context-intelligence's signals-reference,
tuned conservatively; all constants in one module, documented):

| pattern_kind | fires when |
|---|---|
| `compaction_storm` | ≥3 compaction events within a 10-minute window |
| `stuck_loop` | same tool called with identical arguments ≥4 times consecutively |
| `resume_storm` | ≥3 resumes of one session within 30 minutes |
| `iteration_runaway` | ≥25 tool calls with no intervening user message |

`PatternSignal` gains fields (additive, serde-compatible):

```rust
pub struct PatternSignal {
    pub session_id: String,
    pub description: String,
    pub pattern_kind: String,   // stable snake_case id from the table above
    pub evidence: String,       // e.g. "4 compactions 09:01-09:08"
}
```

Pattern signals flow through the existing pipeline unchanged: digest section,
tracker filing, processed-session dedup. No new binary, no new stage.

## W3 design: cost-weighted digests

Additive reader method, same pattern as `load_events`:

```rust
pub struct SessionStats {
    /// Sum of per-call cost_usd. String-decimal to preserve upstream precision;
    /// None when no call carried a cost (e.g. unpriced models).
    pub cost_usd: Option<String>,
    pub input_tokens: u64,
    pub output_tokens: u64,
    /// Sub-agent role parsed from session-id suffix ("<uuid>_<role>"), if any.
    pub role: Option<String>,
    pub model_costs: BTreeMap<String, String>, // model -> summed cost
}

fn load_stats(&self, handle: &TranscriptHandle)
    -> Result<Option<SessionStats>, JilogReviewError> { Ok(None) }
```

Implemented by `amplifier` and `context-intelligence` readers (sum
`data.usage.cost_usd` across `llm:response` events; Decimal math via
`rust_decimal`, never floats). A `claude-code` implementation (usage blocks in
assistant messages) is a stretch goal, not required for v0.2.0; codex, copilot,
and generic keep the None default.

Digest additions:
- A "Spend" section: total, per-role table, per-model table. Rendered only
  when at least one session has stats — silent otherwise, no empty sections.
- Cost-weighting on the existing week-over-week check: recurring signals are
  annotated with the summed cost of the sessions they occurred in ("this
  correction pattern recurred in sessions totaling $4.20").

Explicit boundary: jilog reports spend it observed in session files. It does
not fetch prices, maintain rate tables, or reconcile with provider billing.

## W4 design: remove beads tracker

Delete `crates/jilog-review/src/trackers/beads.rs`, its registration, config
variant, tests, and README references. Config files naming `tracker = "beads"`
fail loudly at load with a message naming kata/github/none as the options.

## W1 design: release hygiene

- README: CI badge (rust.yml exists), a real sample digest (trimmed, from a
  fresh run after W2/W3 land so it shows Pattern + Spend sections), and a
  quickstart that goes install → configure one reader → `jilog review` →
  digest in under five minutes.
- Tag `v0.2.0` (workspace version bump from 0.1.0) with release notes after
  W2–W4 merge. `cargo install --git ... --tag v0.2.0` documented alongside
  the moving-main install.

## Testing

- Detector unit tests with synthetic `SessionEvent` fixtures per threshold
  (fires at threshold, silent below, window edges).
- Stats tests: Decimal precision (0.1-style values), null-cost sessions,
  role parsing from session-id suffix, mixed priced/unpriced models.
- One integration test per implementing reader: fixture events.jsonl →
  events + stats → digest contains Pattern + Spend sections.
- Beads removal: config with `tracker = "beads"` produces the loud error.

## Order

W4 (small, unblocks docs) → W2 → W3 → W1 (README/sample/tag last, so the
sample digest is real). Catalog registration PR re-opens after the tag.
